# RTX 5060 Ti CUDA occupancy check — 2026-10-04

The fork keeps the upstream Goldilocks field and Poseidon2 consensus hash. Its first GPU change adjusts the CUDA kernel's `__launch_bounds__` occupancy target from `(256, 4)` to `(256, 2)` while keeping the same 256 threads per block and the same nonce search. NVIDIA's driver JIT then reports 86 registers and 0 bytes of local memory per thread for `mining_main`, instead of 64 registers and 8 bytes of local memory on the baseline.

Local tests used a 16 GB RTX 5060 Ti, CUDA 13, the same 32 million nonce batch, GPU only, and source builds with Rust 1.93. Alternating 20-second benchmark runs reported 230.20, 233.25, and 230.10 MH/s for baseline, `(256, 3)`, and baseline; median active GPU draws were 132.27, 133.07, and 132.12 W. A later `(256, 2)` / baseline pair reported **234.48 / 230.22 MH/s**, with **131.18 / 131.20 W** median active GPU draws. That is a roughly **1.85%** short-run speed gain at essentially the same sampled GPU power. All runs used the complete miner benchmark; they do not measure whole-computer wall power. Short samples and changing clocks limit the precision of the gain.

The release-mode `engine-cuda` suite passed all 10 tests with the `(256, 2)` kernel, including CPU comparison across nonce carries, field arithmetic, target boundaries, and a CPU-verified solution. A 35-second live Quanpool run logged jobs near 234–235 MH/s. The address-specific pool API increased from 111 to **123 accepted shares**, with zero stale and zero invalid, and reported **0.000010576048 QTC pending** afterward. That pending credit is pool accounting, not an on-chain payout or a sale. The production payout address equals the project fee address, so fee switching was omitted for this local run.

The isolated build and benchmark logs are retained locally under ignored `.runtime/research/quantus-occupancy-tune` and `.runtime/research/quantus-*.log` in the dashboard project.

## Fused internal round

The kernel already contained `mul128_add_wide`, a PTX routine that combines a 64-by-64-bit product with the 96-bit Poseidon2 row sum and round constant. The internal round was still calling `mul64wide` followed by `add128_wide` for each of its 12 lanes. The selected change uses the existing fused routine for those lanes, leaving the Goldilocks reduction, round schedule, target comparison, and fee routing in place. Its documented operand bounds hold for the internal-round diagonal constants and row sums.

In an isolated checkout, all 10 release-mode `engine-cuda` tests passed, including CPU hash comparison and a CPU-verified solution. Four adjacent 20-second full-miner runs in baseline/fused/fused/baseline order measured **236.18 / 250.03 / 250.06 / 236.19 MH/s**. Median active GPU power samples were **132.69 / 134.41 / 134.73 / 133.21 W**. The fused variant is about 5.9% faster and about 4.6% higher in hashes per sampled GPU watt over this short sequence. These are not whole-computer outlet readings, and changing clocks or background GPU use may affect longer runs.

A short live Quanpool run with the fused build raised this local address's 24-hour accepted shares from **135 to 148**, with zero stale and zero invalid. The miner logged jobs near 250 MH/s. The local mining wallet equals the project fee address, so this run did not exercise fee switching. It establishes pool share acceptance, not a completed payout or long-term profitability. The isolated source, build, and local benchmark script are retained under the dashboard project's ignored `.runtime/research/quantus-fused-round/` directory; the live log is ignored at `.runtime/research/quantus-fused-live.log`.

## Goldilocks product experiment, 2026-10-04

An isolated `sm_120` source build replaced the generic 64-by-64-bit wide product used by the S-box with four explicit 32-bit partial products and a PTX carry chain. The original CUDA kernel compiled with **86 registers per mining thread** and no spills; the PTX variant used **64 registers** and no spills. All 10 release-mode CUDA tests passed, including full GPU/CPU hash comparisons and a CPU-verified solution. Lower register use was not enough to improve the complete miner: alternating 20-second baseline/variant/variant/baseline runs reported **251.04 / 248.41 / 245.44 / 252.85 MH/s**. Median active GPU power samples were **135.43 / 135.32 / 135.24 / 135.57 W**. The PTX change was rejected and is not in the release miner. The isolated source, binary, benchmark logs, and exact results are retained in the dashboard project's ignored `.runtime/research/quantus-mul-tune/` and `quantus-mul-*` files.
